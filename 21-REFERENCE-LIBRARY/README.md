# 21 — Reference Library

Look things up here. This subject is not for studying in order — it is the shelf you reach for
while working, written so a single page answers a question in under a minute.

## What this subject covers

- `glossary.md` — every technical term used in the curriculum, each defined in one paragraph with
  a link to the lesson that explains it properly.
- `common-errors.md` — the error messages learners meet most, each with cause, diagnosis, and fix.
- `command-reference.md` — the terminal, package, and tool commands worth memorizing.
- `git-reference.md` — Git operations by goal ("undo my last commit", "what did this file look like
  last Tuesday"), not by flag.
- `sql-reference.md` — syntax patterns for the queries you write weekly.
- `http-status-codes.md` — status codes grouped by meaning, with when-to-use-which guidance.
- `java-reference.md` — syntax and API quick lookups for the Java material.
- `javascript-reference.md` — the same for JavaScript and TypeScript.
- `linux-reference.md` — filesystem, permissions, processes, and services.
- `docker-reference.md` — commands and Dockerfile patterns.
- `official-resources.md` — curated links to official documentation only, with one line on what
  each is best for.

## Why it matters

Professional development is mostly retrieval under time pressure: a broken build, a confusing
status code, a Git state you have never been in. Having a trusted, version-pinned, curriculum-
consistent reference beats searching a results page full of answers for other people's tool
versions — and every page here links back to the lesson that teaches the concept properly.

## Prerequisites

None to *read* these pages; they are self-contained. But you will get far more out of them after
studying the subjects they reference — this is a companion to the curriculum, not a shortcut
through it.

## Exercises and practice

Two habits beat drills here:

1. **Contribute your misses.** When an error costs you more than ten minutes and is not yet in
   `common-errors.md`, add it — writing the entry is the retrieval practice.
2. **Self-quiz the status codes and Git operations.** Cover the right-hand column and name the
   command or meaning.

## Expected outcomes

You can resolve a common error from its message alone, find the right Git operation without
searching, and know exactly which official document to open — the practical definition of being
independent as a developer.
