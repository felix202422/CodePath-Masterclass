## 1. Rebuild the scaffold and annotate it

```bash
flutter create scaffold && cd scaffold
```

Executed tree, annotated as the exercise asks:

```
scaffold/
├── lib/main.dart            # YOUR code — the only folder all platforms share
├── test/                    # YOUR tests — run by flutter test, never shipped
├── android/                 # native shell: AndroidManifest.xml, Gradle, signing
│   └── app/src/main/AndroidManifest.xml   # read by the OS at install/run
├── ios/                     # native shell: Info.plist, Xcode project
│   └── Runner/Info.plist                  # read by iOS at install/run
├── web/  windows/  macos/  linux/          # same pattern, one folder each
└── pubspec.yaml             # deps + assets — read by the Flutter tool
```

The two facts: **`lib/` and `test/` are platform-agnostic** (one Dart codebase), and
**each platform folder is a native host project** the OS vendors read — that split *is*
"one codebase, native shells". `flutter analyze` on this tree (executed): `No issues
found! (ran in 94.7s)` cold; `flutter test` → `+1: All tests passed!`.

## 2. Platform branching you can observe

```dart
void main() => runApp(Text('ran on windows=${Platform.isWindows}',
                           textDirection: TextDirection.ltr));
```

Executed capture: `Platform.isWindows=true`. What `dart:io`'s platform truth does to
widget tests: it is fixed at process start, so a test on Windows cannot honestly assert
the `isAndroid` branch — guard platform-specific code behind an injectable predicate (or
use `defaultTargetPlatform` + `debugDefaultTargetPlatformOverride`) so tests can *pretend*.

## 3. A cold start, timed

Executed: `flutter analyze` cold `ran in 94.7s` (first run: SDK snapshot + package
resolution) vs warm runs in seconds; `flutter test` first run compiles the test kernel,
later runs reuse it. The number to quote in CI: the **warm** one — cold time is
one-time machine provisioning, and pinning it would make every CI build look broken.

## 4. Independent — regenerate vs preserve (reference shape)

| Item | Verdict | Why |
|---|---|---|
| `lib/`, `test/`, `pubspec.yaml` | yours (in git) | the actual app |
| platform folders (boilerplate) | regenerable | `flutter create .` rebuilds them |
| `applicationId` / bundle id | **preserve** | identity — changing it is a new app |
| upload keystore / signing keys | **irreplaceable** | not generated by any command; custody = ability to update |
| custom native code (plugins you forked) | **preserve** | regeneration overwrites with boilerplate |

The one-line rule: git tracks what you wrote; the store tracks what you signed — anything
in either category is not regenerable.
